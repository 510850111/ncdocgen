## 安装与启动

### Q: 程序启动后立即崩溃怎么办？

**A:** 可能原因和解决方法：

1. **缺少依赖**
   - 确保使用的是打包后的exe文件（包含所有依赖）
   - 如果是源码运行，检查是否安装了requirements.txt中的依赖

2. **权限问题**
   - 尝试以管理员身份运行
   - 检查程序目录是否有写入权限

3. **日志查看**
   - 检查 `log/` 目录下的最新日志文件
   - 查看具体的错误信息

### Q: 是否支持Linux或macOS？

**A:** 当前发布的exe仅支持Windows。但Python源码是跨平台的：

```bash
# Linux/macOS用户可以从源码运行
pip install -r requirements.txt
python -m ncdocgen
```

### Q: 如何彻底卸载程序？

**A:** ncdocgen是绿色软件，直接删除即可：

1. 删除 `ncdocgen.exe`
2. 删除生成的 `Key.txt`（如不需要保留）
3. 删除 `log/` 目录
4. 删除 `dist/` 目录（如果有）

## Key.txt相关

### Q: Key.txt是什么？有什么用？

**A:** Key.txt是关键字定义文件，包含：
- 宏定义（如`#define MAX_SIZE 100`中的MAX_SIZE）
- 结构体、枚举、联合体定义
- typedef定义的类型

**作用**：帮助程序区分用户标识符和系统关键字，正确解析代码。

### Q: 为什么首次使用必须生成Key.txt？

**A:** 程序需要知道项目中的自定义类型和宏定义，才能正确解析代码。例如：

```c
// 如果没有Key.txt，程序不知道UINT8是类型还是变量
UINT8 buffer[10];
```

### Q: Key.txt可以手动编辑吗？

**A:** 可以。格式如下：

```
# 注释以#开头
# 格式: 关键字=类型

# 宏定义
MAX_SIZE=AUTO
MIN_SIZE=AUTO

# 结构体
MyStruct=AUTO

# 枚举
StatusCode=AUTO
```

### Q: 项目代码更新后需要重新生成Key.txt吗？

**A:** 建议重新生成。如果：
- 添加了新的结构体/枚举
- 定义了新的宏
- 添加了新的typedef

重新生成可以确保解析准确性。

## 文档生成

### Q: 生成的Markdown文件打不开？

**A:** 

1. **使用正确的编辑器**
   - 推荐使用Typora、VSCode等支持Markdown的编辑器
   - Windows记事本可能显示格式混乱

2. **检查文件编码**
   - 文件使用UTF-8编码
   - 确保编辑器支持UTF-8

3. **图片不显示**
   - 流程图使用PlantUML代码块
   - 需要安装PlantUML插件或转换为图片

### Q: 可以生成Word或PDF吗？

**A:** 直接生成不支持，但可以转换：

**Markdown转Word：**
- 使用Typora：文件 -> 导出 -> Word
- 使用Pandoc：`pandoc input.md -o output.docx`

**Markdown转PDF：**
- 使用Typora：文件 -> 导出 -> PDF
- 使用VSCode插件

### Q: 为什么生成的文档中缺少某些函数？

**A:** 可能原因：

1. **函数未在选中的文件中**
   - 检查输入文件列表
   - 确保包含该函数的定义文件

2. **函数缺少doxygen注释**
   - 程序提取 `/** */` 格式的注释
   - 确保函数头有此格式注释

3. **语法错误**
   - 函数定义存在语法错误
   - 检查源文件是否能正常编译

### Q: 如何只生成特定函数的文档？

**A:** 当前版本不支持按函数筛选，可以：

1. 将目标函数提取到单独的文件
2. 只选择该文件进行处理

## 流程图

### Q: 流程图中的中文显示乱码？

**A:** 

1. **确保文件编码为UTF-8**
   - 源文件保存为UTF-8编码

2. **直接使用中文字符串（v1.0.0+）**
   ```c
   /** 初始化系统 */
   void init(void) { }
   
   /** 设置模式为"正常工作状态" */
   void set_mode(void) { }
   ```

3. **PlantUML配置**
   - 如果导出为图片，确保PlantUML支持中文
   - 可在PlantUML代码中添加：`skinparam defaultFontName Microsoft YaHei`

### Q: 流程图太深太复杂怎么办？

**A:** 

1. **调整流程图深度**
   - 在GUI中减小"流程图深度"值
   - 命令行使用 `-d 5`（数字越小越浅）

2. **简化代码逻辑**
   - 将复杂函数拆分为多个小函数
   - 提取公共逻辑为子函数

### Q: 为什么switch-case的流程图不对？

**A:** 

- 确保case语句格式正确
- 避免复杂的case嵌套
- 每个case尽量有break

### Q: 如何自定义流程图样式？

**A:** 当前版本不支持直接自定义，可以：

1. 生成后手动修改PlantUML代码
2. 在模板中添加PlantUML主题设置

## 性能问题

### Q: 处理大项目时很慢怎么办？

**A:** 

1. **分批处理**
   - 不要一次性选择所有文件
   - 按模块分批处理

2. **减少流程图深度**
   - 深度越大处理越慢
   - 设置为5-8通常足够

3. **关闭详细日志**
   - 取消勾选"详细日志"

4. **硬件升级**
   - 更大的内存有助于处理大文件

### Q: 内存不足怎么办？

**A:** 

1. 减少同时处理的文件数量
2. 重启程序释放内存
3. 关闭其他占用内存的程序

## 错误排查

### Q: "cannot import name 'xxx'" 错误

**A:** 

- 可能是文件路径问题
- 尝试重新打包或使用源码运行
- 检查是否修改了系统Python环境

### Q: "文件不存在"错误但文件确实存在

**A:** 

1. 检查文件路径是否包含特殊字符
2. 确保路径没有多余空格
3. 尝试使用短路径（将文件复制到简单路径下）

### Q: 语法错误但代码能正常编译

**A:** 

1. **预处理器宏**
   - 程序不处理宏展开
   - 复杂的宏可能导致解析错误

2. **GCC扩展语法**
   - 某些GCC扩展语法不被支持
   - 尽量使用标准C语法

3. **静默处理**
   - 某些语法错误会被静默处理
   - 不影响流程图生成的可以忽略

### Q: 如何查看详细错误信息？

**A:** 

1. **查看日志文件**
   - 打开 `log/` 目录下的最新日志
   - 查看完整的错误堆栈

2. **启用详细日志**
   - GUI中勾选"详细日志"
   - 命令行使用 `-v` 参数

3. **命令行调试**
   ```bash
   ncdocgen.exe --cli your_file.c -v
   ```

### Q: 如何报告bug？

**A:** 

1. 准备以下信息：
   - 程序版本号
   - 操作系统版本
   - 复现步骤
   - 错误日志（`log/` 目录下）
   - 示例代码（如果可以提供）

2. 提交到Issue跟踪系统
